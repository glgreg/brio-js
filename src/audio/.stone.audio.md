# Audio Mixer

## Purpose and Design Decisions

`BrioAudioMixer` (`src/audio/BrioAudioMixer.ts`) is the single global mixing stage for every `BrioAudio` asset. It is a
static class (no instances) because a page should own exactly one `AudioContext`: browsers limit the number of
contexts, and one shared graph lets bus volumes apply to every sound at once.

- **Lazy context**: the `context` getter creates the `AudioContext` (or `webkitAudioContext`) on first access, never
  at import time, so importing the engine in Node.js, jsdom or a worker has no side effects. A failed constructor is
  cached as `null`, and later reads return `undefined` without retrying.
- **Bus graph**: three `GainNode`s built by `#createBuses`: `bgm -> master` and `sfx -> master`, with `master ->
  context.destination`. `AudioBusName` is `"master" | "bgm" | "sfx"`; there are no user-defined buses.
- **Bus state lives outside the graph**: `#buses` keeps `{ volume, muted, gain? }` per bus. Volume and mute are stored
  separately so `mute(bus, false)` restores the previous volume; `#applyBus` writes `muted ? 0 : volume` to the gain.
- **Autoplay unlock**: creating the context calls `enableAutoUnlock()`, which installs one shared handler for
  `pointerdown`, `keydown`, `touchend` and `mousedown` on `document`. The handler calls `unlock()`
  (`context.resume()`); the listeners are removed once the context reports `"running"`. Sounds started before the
  gesture (e.g. music in `load()`) are scheduled on the suspended context and become audible at the first interaction.
- **Fallback mode**: without Web Audio, `context` is `undefined`, `busInput()` returns `undefined`, `decode()` returns
  `undefined`, and `unlock()`/`isUnlocked` report `true`. `BrioAudio` then plays through `HTMLAudioElement`, and the
  mixer only provides arithmetic (`effectiveVolume`) plus change notifications (`onVolumeChange`).

## Invariants

- Bus volumes are always finite and within `[0, 1]`: `setVolume` clamps, and a non-finite input becomes `1`. Gain
  values and `HTMLAudioElement.volume` (which throws outside `[0, 1]`) both depend on this.
- `"bgm"` and `"sfx"` always feed `"master"`; `effectiveVolume(bus)` is `bus.volume * master.volume`, `0` when either is
  muted. The fallback path reproduces the Web Audio graph only through this formula, so both paths stay audibly
  equivalent only while the graph topology and the formula agree.
- Every mutation of a bus (`setVolume`, `mute`, and bus creation) runs all `#volumeListeners`. Fallback audios have no
  gain node and re-read `effectiveVolume` only when notified.
- At most one unlock target is registered at a time; `enableAutoUnlock` on the same target is a no-op and on a new
  target removes the old listeners first, so gestures never trigger duplicated `resume()` calls.
- `reset()` closes the context, removes unlock listeners, clears listeners and restores all buses to volume `1`,
  unmuted. Tests rely on it to isolate static state between cases.

## Integration Contracts

- `src/assets/BrioAudio.ts` is the only consumer of the graph:
  - `load()` uses `BrioAudioMixer.context` plus `fetch` to download and `BrioAudioMixer.decode()` into an `AudioBuffer`;
    otherwise it waits for `canplaythrough` on an `HTMLAudioElement`.
  - Each audio owns one per-audio `GainNode` (`#output`, value = per-audio `volume`) connected to
    `busInput(bus)`, falling back to `context.destination`; every voice is an `AudioBufferSourceNode` into that gain.
  - `BrioAudio.bus` is `Exclude<AudioBusName, "master">` (default `"sfx"`); changing it reconnects `#output` to the new
    bus input.
  - In fallback mode, the element subscribes with `onVolumeChange` (marked `@internal`) and sets
    `element.volume = volume * effectiveVolume(bus)`; `dispose()` unsubscribes.
- `pause()`/`resume()` offsets in `BrioAudio` are computed from `context.currentTime`, so `suspend()` on the mixer
  freezes that clock for every audio at once.
- `BrioGame` reaches audio only through `BrioAudio.load()` during `preload()` and `usesWebAudio` for logging; it does
  not call `suspend()` or `unlock()` itself (game pause does not silence audio).
- Public exports: `AudioMixer` (alias of `BrioAudioMixer`) and the `AudioBusName` type from `src/index.ts`.
- Not implemented yet (docs/ROADMAP.md, "Later"): positional audio with `PannerNode` bound to cameras.

## Anti-Patterns

- Creating a separate `AudioContext` in an asset or game code: its sounds bypass the buses and the unlock handling.
- Connecting voices straight to `context.destination` when a bus input exists: bus volume and mute stop applying.
- Accessing `BrioAudioMixer.context` at module top level: it instantiates the context (and installs DOM listeners)
  during import, breaking SSR/Node usage and the lazy-creation design.
- Changing a gain node's value directly instead of `setVolume`/`mute`: fallback listeners are not notified and the
  stored bus state drifts from the graph.
- Treating `unlock()` as callable at any time: it only succeeds inside or after a user gesture; outside one it resolves
  `false` or leaves the context suspended.
