# Object Facades and Transforms

## Purpose and Design Decisions

`BrioObject2D` and `BrioObject3D` are the public, beginner-facing entities (ADR 0002, ADR 0004). They are thin
handles (`entityId` plus `entityGeneration`) with a transform (`BrioTransform2D` / `BrioTransform3D`) whose spatial
fields are atomic views (`BrioVec2`, `BrioVec3`, `BrioQuat`) bound to an ECS slot by `bindECS(storage, id, adopt)`.
2D and 3D are separate concrete classes so 2D code never allocates 3D state.

- Unbound transforms keep values in private fields. Once bound, the views and the scalar getters (2D `rotation`,
  `opacity`, `layer`; 3D `opacity`, `layer`; `visibility` in both) read and write the ECS slot directly
  (`transform2D` / `transform3D`, visibility in the `visual` buffer), and every setter marks
  `DirtyFlag.TRANSFORM | DirtyFlag.RENDER`.
- `bindECS(..., adopt = false)` pushes the facade values into the slot (new entity); `adopt = true` pulls the slot
  values into the facade (after a snapshot restore). `unbindECS()` copies the last slot values back into private
  fields and detaches, so a destroyed object stays readable but can no longer write into a recycled slot.
- `BrioTransform2D` derives `renderSize = |size * scale|`, clamps `pivot` and `opacity` to `[0, 1]`, and turns
  negative size or scale components into `flip` flags. `worldPosition`, `worldRotation` and `worldScale` are computed
  recursively from the parent on each access.
- `BrioTransform3D` keeps Euler `rotation` and `quaternion` in sync through change callbacks guarded by
  `#syncingRotation`, and caches `localMatrix` / `worldMatrix` behind `#localDirty` / `#worldDirty` plus version
  counters (`#localVersion`, `#worldVersion`) so a child rebuilds its world matrix whenever an ancestor's changed.
- `BrioLight` (`directional`, `ambient`, `hemisphere`) is not ECS-backed: its `version` counter increments on every
  change and is part of the cache key in `rendering/lighting.ts`, so light data is rebuilt only when a light changes.

## Invariants

- Dirty marking propagates to all children (`#markDirty` / `#markWorldDirty` recurse), because a child's world
  transform and any `"static"` layer cache that contains it depend on the parent.
- `addChild` rejects `child === this` and detaches the child from its previous parent first, so each transform has
  at most one parent. Longer cycles (A under B under A) are not detected.
- The 3D matrix cache is invalidated through the facade (setters, view callbacks, `bindECS` with `adopt`) and, while
  bound, by direct writes into the slot: `localMatrix` keeps the 10 floats it was built from (position, scale,
  quaternion) and compares them with the slot on access, a fixed zero-allocation cost. The matrix reads the
  quaternion, so direct writes must update `[9-12]`; writing only the Euler slots `[6-8]` does not rotate it.
- `BrioObject3D.addChild` mirrors the object hierarchy into the transform hierarchy, so `forEachDescendant` and
  `worldMatrix` agree; model parts each get their own ECS slot when their root is registered (game or scene).
- `BrioLight.intensity` is clamped to `>= 0` and non-finite values become 0, so lighting uniforms never receive NaN.

## Integration Contracts

- Owners (`BrioGame`, `BrioScene`) create the entity, set `entityId` and `entityGeneration`, then call `bindECS`. On
  removal they destroy the entity, call `unbindECS()` and set `entityId = -1`. `entityId < 0` means "not registered"
  and makes `BrioCompositor` treat the object as dirty.
- `transform.layer` is the depth inside a `BrioLayer` (sort key of `BrioLayer.getSortedObjects`), not the layer
  itself; TODO.md proposes renaming it to `depth` to avoid the collision with the GLOSSARY term "Layer".
- `BrioObject2D.collision` / `BrioObject3D.collision` are plain JS objects consumed by `BrioCollision` and physics.
  `addCollisionMask` is a no-op when a 2D collision already exists, while `addCollider3D` replaces the 3D one.
- `BrioObject2D.clone` copies transform values and collision. `BrioObject3D.clone` copies position, scale,
  quaternion, visibility, opacity, layer and collision, but not children or parts.

## Anti-Patterns

- Caching transform values in other fields instead of reading the views: the slot is the source of truth and can
  change through a snapshot restore.
- Writing through a facade whose `entityGeneration` no longer matches `world.generationOf(entityId)`.
- Allocating closures per frame in transforms; the view callbacks are created once in the constructor.

Discrepancies: ADR 0002 states that facades never hold authoritative component state in private fields, but `flip`,
`sprite`, `mesh`, `material`, `collision` and the hierarchy still live only in JS fields, so binary snapshots do not
capture them, and the `collider` / `rigidBody` buffers stay unused. Moving them into ECS buffers is a deferred
design change; only `visibility` moved (into the `visual` visibility slot).
