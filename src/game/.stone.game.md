# Game Entry Point and Main Loop

## Purpose and Design Decisions

- `BrioGame` is the single entry point (ADR 0004). The constructor accepts either `(width, height, container, preset | CanvasRenderingContext2DSettings)` or a `BrioGameConfig` object. It creates the `<canvas>`, its 2D context, an `ECSWorld` (`maxEntities` defaults to 4096), a `BrioSpriteRenderer`, a `BrioCompositor`, a `BrioUpdater` and a `BrioAssetManager`, and registers a `"default"` layer (`DEFAULT_LAYER_NAME`, order 0, policy `"dynamic"`).
- Presets: `"2d"` (the default) creates the `ECSWorld` with `transform3D: false`, so 2D games carry no 3D transform buffer. `"3d"` and `"hybrid"` allocate both buffers and queue `BrioRenderer.initBackend(canvas, renderBackend, onFailure)`. Each backend that fails to initialize is logged as a warning before the next one is tried. If none initializes, 3D passes stay disabled.
- Lifecycle: `preload()`, `load()`, `update()` and `setScene()` append stages to one promise chain (`#chainLifecycle`), so they run in call order even though `preload` is async. When a stage throws, the state becomes `GameState.ERROR`, the error is logged once, and later stages are skipped. `ready()` returns the chain.
- `preload()` registers `BrioMesh`/`BrioMaterial` instances as they are, then awaits sprite sheets (`texture.decode()`), sprites, atlases (`mount()`), audios (`load()`) and models (`load()`). A loaded model's meshes and materials are copied into the shared `meshes`/`materials` maps, and its `warnings` are logged. An empty asset list is valid. Failures reject with an `Error` naming the asset; the lifecycle enters `GameState.ERROR`, `lifecycleError` keeps the error and `ready()` rejects with it (the internal chain itself stays resolved so later stages are skipped, not unhandled).
- Every preloaded asset records its owners (the game for `preload()`, the scene for `BrioScene.preload()`). `onLoadProgress()` listeners receive `{ loaded, total, ratio, asset, scene }` after each asset. `unloadAsset()` removes an asset from the registries and frees it (audio `dispose()`, mesh and texture GPU copies through `RenderBackend.releaseMesh` / `releaseTexture`, decoded bitmaps); a texture is kept while another registered sprite sheet, atlas or material uses it. `removeScene(name)` refuses the active scene, destroys the scene, and unloads the assets whose last owner was that scene.
- `load()` registers the returned content in three passes: layers, then cameras, tile maps and lights, then objects. It then calls `createSnapshot()`, so `restart()` and `useSnapshot()` have an initial state.
- Frame step (`#step`, shared by the `requestAnimationFrame` loop and the manual `step(dt)`), in order: set the logical-pixel transform (`setTransform(pixelRatio, ...)`), clear the screen, poll gamepads (`useGamepad()` polls connected pads once per frame here), `timer.update`, draw the debug grid, run fixed steps, call the `update()` callback, `activeScene.step(dt)`, dispatch collision events (2D, then 3D outside the `"2d"` preset), call `update(dt)` on every game-level `BrioCamera2D`, apply interpolation, `renderFrame()`, restore interpolation, and roll the input state into the previous-frame state: `game.input.endFrame()` first (it reads the controllers' latched edges), then `game.keyboard.endFrame()`, the mouse and gamepad `endFrame()`, and `BrioKeyboard.syncGlobalFrame()`, so `BrioKeyboard.globalIsUp` sees the same frame boundary as `game.keyboard.isUp`.
- Input: `game.input` (`BrioInputMap`) exists from construction; `useKeyboard()` / `useMouse()` / `useTouch()` / `useGamepad()` attach their controller to it. Mouse and touch receive the game as `logicalSize`, so positions are in logical pixels whatever the canvas CSS size or pixel ratio. `end()` cancels a pending binding capture and exits a pointer lock held by the canvas.
- Screen: the canvas backing store is `width x height` times `pixelRatio` (the `pixelRatio` option or `devicePixelRatio` capped at `maxPixelRatio` for `"auto"`, times the display scale of `useFullScreen("fit")`), and its CSS size is the logical size times the display scale. `resize()` changes the logical size. `useFullScreen("resize" | "fit")` keeps exactly one window `resize` listener (replaced on every call, removed by `end()`).
- Pause and audio: `pause()` stops the loop and calls `BrioAudioMixer.suspend()`, which holds the shared context suspended so a user gesture does not auto-unlock audio while the game is paused. `resume()` calls `BrioAudioMixer.resume()` only when this game's `pause()` took the hold. In fallback mode (`HTMLAudioElement`) the hold has no audible effect.
- Fixed step: `fixedUpdate()` sets `fixedTimestep` to 1/60 if it is 0. The accumulator runs at most `maxFixedSteps` (default 5) steps per frame. When the step cap is hit and time is still pending, the backlog is reduced to `accumulator % step` to avoid the spiral of death. `deltaTime` is clamped to `maxDeltaTime` (default 0.1 s, `0` disables the clamp). The FPS overlay uses the unclamped time.
- Interpolation (`interpolate: true`): each object's position before a fixed step is recorded in a `WeakMap`. During rendering, the position is temporarily set to `lerp(previous, current, interpolationAlpha)` and restored right after. 2D writes use `setSilent`, then `markDirty()` makes cached `"static"` layers redraw at the real position. The loop allocates nothing per frame: visitors are bound once as fields, the simulated positions go into a pool of records that only grows when more objects move than in any earlier frame (with a live count, references dropped after restore), and the keyboard frame is closed through `BrioKeyboard.endFrame()`, which updates the previous-frame map in place.
- `BrioAssetManager` is a plain set of registries: `Map`s keyed by name for assets, and `BrioRegistry` for `objects3d`, `cameras2D` and `cameras3D`. The compositor iterates those dense lists. `BrioUpdater` and the `load()` asset accessor return empty fallback instances (`getEmptyInstance()`) for unknown names and log the error once (`loggedErrors`). They do not throw.
- `BrioSpriteRenderer` (described in architecture.md as the legacy sprite renderer) draws `BrioObject2D` with `ctx.drawImage` plus the debug overlays. `BrioCanvasBackground` syncs `game.background` to the canvas CSS.

## Invariants

- Adding a `BrioObject3D` to a `"2d"` game throws in `#bindObject3DToECS` because the storage has no 3D buffer (`storage.has3D` is false). Without this check, the object would write into memory that does not exist.
- Every registered object holds a live `(entityId, entityGeneration)` handle. `destroy()` calls `destroyEntity`, then `transform.unbindECS()`, and sets `entityId = -1`. A stale reference therefore cannot write into a recycled slot. 3D objects release every descendant part as well.
- `destroy()` never deletes a shared `BrioSprite`. Sprites are flyweights used by many objects, and only `removeObject(sprite)` unregisters one.
- A checkpoint (`GameStateCapture`) stores the ECS bytes (`BrioSerializer.captureSnapshot`), each object together with its entityId, layer and facade state (`captureState()`: sprite, flip, parent, tag, collider, text; mesh, material, collider and parts for 3D), 3D descendant parts, the tiles of every registered tile map, the `game.random` state and the active scene's own state. Restores also clear the collision contact sets, so overlapping objects report a fresh `enter`. On restore, the bytes are written back, objects registered after the capture are unbound, and every captured handle is rebound with `bindECS(storage, id, true)`. The random state is restored too, so replays draw the same sequence. The fixed accumulator is reset to 0.
- `addCamera()` sets `camera.random = game.random` on a `BrioCamera2D` that has no random source yet, so screen shake is reproducible with a fixed `seed`.
- Each `BrioObject2D` belongs to exactly one registered layer. `addObject` uses `layerName` if given, keeps the object in a layer that already holds it, or falls back to `"default"`. `#objectLayers` (a `WeakMap`) caches this lookup.

## Integration Contracts

- Each frame, the compositor gets `[gameSource, activeScene.compositorSource]` as `CompositorSource`s (a reused array). `game.renderStats` exposes the compositor's `CompositorStats`. `game.renderBackend` exposes the backend that initialized.
- `setScene(name)` activates an already-loaded scene immediately. Otherwise it queues preload and `mount()` on the lifecycle chain, and a later `setScene` call wins. The previous scene is paused only when the new one activates.
- `instantiate(prefab)` is generic over `BrioObject2D` (and subclasses) and `BrioObject3D` and returns the prefab's type. Clones are named `"<name>-<n>"`, skipping names already in use. 2D clones are built with `BrioObject2D.clone()` (type, transform, tag, collider), inherit the prefab's collision listeners, copy component data with `ECSWorld.instantiateFrom` and join the prefab's layer; 3D clones are deep copies (`BrioObject3D.clone`) registered through `addObject()`.
- `addTileMap(map, layerName = "default")` (also used for maps returned by `load()`) registers the map and adds it to that layer unless a registered layer already holds it.
- `end()` cancels the loop, removes input listeners, stops every registered `BrioAudio` and releases the mixer hold taken by `pause()`, disposes the 3D backend (and unsets it in the compositor), unbinds every handle, clears registries (including `meshes`, `materials` and `models`) and the ECS, and re-adds the `"default"` layer. 3D passes stay disabled after `end()`. A `#session` counter makes a backend that is still initializing when `end()` runs get disposed on arrival, and a backend stage that has not started yet is skipped.

## Anti-Patterns

- Calling `requestAnimationFrame` or advancing objects outside `#step`. Tests and replays use `game.step(dt)`, which applies the same clamp, fixed steps and render.
- Reading object positions inside `renderFrame` while interpolation is on and treating them as simulation state. Those positions are interpolated values that get restored afterwards.
- Known limitation (docs/ROADMAP.md): the 3D backends and model loaders are loaded on demand, but `BrioGame` still references the 3D object, camera and math classes, so a 2D-only bundle is about 164 kB minified (48 kB gzip).
