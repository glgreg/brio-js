# Rendering

## Purpose and Design Decisions

- ADR 0001 rejected three.js (size, scene graph that conflicts with the ECS, no WebGL1/Canvas2D fallback). In its place, the engine owns a zero-dependency pipeline behind `RenderBackend` (`contracts/RenderBackend.ts`): `init(surface)`, `beginFrame(viewport, clearColor?)`, optional `setLights(env)`, `renderMesh3D(mesh, material, world, viewProj)`, `endFrame()`, `dispose()`. Backends draw 3D only. 2D content is drawn by `BrioSpriteRenderer` on the canvas 2D context. ADR 0007 allows adapting MIT shader and rendering code from three.js and Godot into this pipeline, with a file header and an entry in `THIRD_PARTY_NOTICES.md`; that adds no runtime dependency.
- `BrioRenderer` is a static factory. `BACKEND_CASCADE` is `webgpu -> webgl2 -> webgl1 -> canvas2d`. Only `webgl2` (`WebGL2Backend`) and `canvas2d` (`Canvas2DBackend`) are registered. `backendCandidates(preferred)` lists the preferred backend first when it is usable, then every other usable backend, where usable means "registered and reported by `PlatformAdapter.detectCapabilities()`". `initBackend()` tries the candidates in order. A backend whose `init()` resolves `false` or throws is disposed, reported through `onFailure`, and the next one is tried: a blocklisted GPU driver or a context limit should cost one tier, not a drop straight to the software rasterizer. `registerBackend(type, factory)` is how WebGPU (planned for v0.2) plugs in.
- `WebGL2Backend` renders into a private WebGL2 canvas and, in `endFrame()`, copies the viewport rectangle onto the target's 2D context with `drawImage`. The single visible canvas therefore keeps 2D layers and the `ui` layer drawn on top of 3D. `renderMesh3D()` only queues pooled `DrawItem`s. `endFrame()` sorts opaque items by program, then material, then front-to-back depth (`compareOpaque`), and sorts transparent items (`opacity < 1`) back-to-front with blending on and depth writes off. Mesh buffers upload once per `BrioMesh` (a `WeakMap` with one VAO each, fixed attribute locations). Programs are cached per feature bitmask (map, lit, flat, alpha test). Redundant GL state changes are skipped. Textures upload as `SRGB8_ALPHA8` with `texStorage2D` and mipmaps, plus anisotropy when available. Lighting runs in linear space, and output is sRGB.
- `Canvas2DBackend` is the universal fallback: a software projector that clips against the near plane (Sutherland-Hodgman, `z >= -w`), culls back faces in screen space, shades with `irradianceLuminance` using cached tone ramps (`SHADE_LEVELS = 64`), and sorts every triangle of the pass back-to-front (Painter's Algorithm, `compareTriangleDepth`). Runs of triangles with the same style are batched into one `fill()`. Wireframe paths are capped at `MAX_WIRE_RUN = 64` triangles because stroke cost grows superlinearly. Opaque triangles are dilated by `SEAM_DILATION_PX = 0.5` to hide antialiasing seams.
- `lighting.ts` reduces `BrioLight`s to a `LightingEnvironment`: linear `ambient`, `sky` and `ground`, up to `MAX_DIRECTIONAL_LIGHTS = 4` directions (pointing toward the light) and colors, plus a `key` string that changes when any value changes. `color.ts` holds `parseCanvasColor`, `srgbToLinear` and `linearToSrgb`.
- `BrioCompositor.renderFrame(ctx, w, h, scale, sources, debug)` renders each `CompositorSource` (game first, then active scene) in this order: one clipped 2D pass per `BrioCamera2D` (a default full-screen camera when there is none), then one 3D pass per `BrioCamera3D`, then the `ui` layers in screen space. After all sources it clears layer dirty flags and calls `world.clearAllDirty()`.

## Invariants

- An unregistered backend type is never selected, and `canvas2d` cannot be unregistered. As a result, `selectBestBackendType()` always returns a type `createBackend()` can instantiate, and the cascade always ends on a working fallback.
- A `"static"` layer is cached per (layer, camera) in an offscreen canvas. It is re-rasterized only when the layer is dirty, an object has `DirtyFlag.RENDER`, or the camera position, zoom, rotation, viewport size or `game.scale` changes. This invariant depends on cameras that settle exactly (see the cameras stone).
- Before each 3D pass, the compositor sets `camera.aspect` to the viewport's pixel aspect so projections are undistorted in split-screen. It also sets `camera.size` for 2D passes, which keeps follow, deadzone and culling math consistent with the real viewport size.
- `WebGL2Backend` flips `frontFace` to CW when the world matrix determinant is negative, because a mirroring transform reverses winding. Back faces are culled unless `doubleSided` or `wireframe` is set.
- The `BrioLights` uniform buffer (std140) is re-uploaded only when `env.key` changes, and `Canvas2DBackend.setLights` returns early on the same key.
- Hot paths allocate nothing per frame: draw items, triangles and clip scratch arrays are pooled, and comparators are module-level functions. A test checks that the compositor neither allocates nor re-sorts layers per frame once their order is stable.
- WebGL context loss: the backend sets `#contextLost` and skips draws. On `webglcontextrestored` it rebuilds every GPU resource from the CPU-side meshes and textures.

## Integration Contracts

- Consumers: `BrioGame` (`initBackend`, `compositor.configure3D(backend, meshes, materials)`) and `BrioScene` (its `compositorSource`). 3D objects resolve `obj.mesh` and `obj.material` by name in the asset maps. When the material is missing, the gray `mat_brio_default` is used. When the mesh is missing, the object is skipped. Children are rendered recursively through `BrioObject3D.children`, and only root objects start a traversal.
- Without lights, a source uses `BrioLight.createDefaultRig()`.
- `beginFrame` with no clear color, or with a translucent one, erases the 2D content under the viewport. Both backends share this behavior.
- Mesh geometry is treated as immutable after the first draw: `WebGL2Backend` has no versioned re-upload.

## Additions in v0.2

- **On-demand backends.** `BrioRenderer`'s built-in factories `import()` `./WebGL2Backend` and `./Canvas2DBackend`, so
  bundlers split both modules out and a `"2d"` game, which never calls `initBackend()`, does not load them. Factories
  are `RenderBackendFactory` (sync or async); a factory that rejects (offline chunk, CSP) counts as a failed backend
  and the cascade moves on. `createBackend()` is therefore asynchronous.
- **Pixel ratio.** `renderFrame(..., pixelRatio)` receives `game.pixelRatio`; the main context already maps logical
  pixels (`BrioGame` sets `setTransform(ratio, ...)` at the start of every frame), so 2D passes, viewports and `ui`
  layers stay in logical units. `"static"` layer caches are allocated at `vw * ratio` x `vh * ratio`, rasterized
  under the same transform and drawn back with `drawImage(cache, vx, vy, vw, vh)`; a pixel ratio change invalidates
  them. `Canvas2DBackend.beginFrame` resets the transform to identity because it projects in canvas pixels, and
  `WebGL2Backend` composites with an identity transform as before.
- **Composition order.** World content of every source (2D camera passes, then 3D passes) is drawn first; the `"ui"`
  layers of all sources come last, so a game-level HUD stays above the active scene.
- **Tile maps.** For each layer, `drawTileMaps()` (`BrioTileMapRenderer.ts`, internal) runs after the camera
  transform and before the layer's objects, with the visible world rectangle (expanded to the bounding circle when
  the camera is rotated) and `gameScale`. Maps are split into chunks (16x16 tiles, fewer for big tiles so a raster
  stays at most 2048 px) rasterized lazily into offscreen surfaces cached in a module-level `WeakMap`; `setTile`
  invalidates one chunk, tileset/size changes all of them, at most 256 surfaces per map are kept (least recently
  drawn reused). A tileset whose texture is not decoded yet draws nothing and retries next frame. `"static"` layers
  redraw when one of their maps' `version` changed. `tileChunksDrawn` counts chunk images per frame.
- **3D frustum culling.** Each mesh gets a bounding sphere (box center, farthest vertex) computed once and cached in a
  `WeakMap` (positions are treated as immutable); the center is transformed by the object's world matrix and the
  radius scaled by its largest axis scale before `BrioCamera3D.isSphereInFrustum`. Meshes without vertices are never
  culled. `objects3DDrawn` / `objects3DCulled` report the result.
- **Resource release.** `RenderBackend.releaseMesh?` / `releaseTexture?` free one GPU copy (`game.unloadAsset()` calls
  them); `WebGL2Backend` deletes the geometry buffers, VAOs (including the wireframe ones) and textures and drops them
  from its owned-resource lists, so a later `dispose()` does not delete them twice.

## S2 Repairs

- `LightingEnvironment.version` (numeric, unique across environments) replaces the string `key`.
  `buildLightingEnvironment` compares the light list and each light's `version` with the previous build
  (`sources`, `sourceVersions`) and returns early when nothing changed, so a steady scene allocates nothing.
- A `BrioCamera3D` without objects still runs `beginFrame` / `endFrame`, clearing its viewport.
- `WebGL2Backend` sorts draw items with `sortInPlace` (`src/tools/sort.ts`, stable merge sort over a reused buffer);
  `Array.prototype.sort` allocated a work buffer per frame and insertion sort is quadratic on lists rebuilt every
  frame.
- `renderMesh3D(mesh, material, world, viewProj, opacity?)`: opacity is per draw item; `Canvas2DBackend` applies it
  through `globalAlpha`.

## Lights, Standard Shading and Pass Parameters

- `LightingEnvironment` holds up to `MAX_DIRECTIONAL_LIGHTS` (4) directional and `MAX_PUNCTUAL_LIGHTS` (8) point / spot
  lights. Capacities are fixed so adding or removing lights never recompiles a program; the counts travel in
  `uLightCount`. Punctual attenuation is `1 / d^decay`, windowed to zero at `range` (`KHR_lights_punctual`), times
  `t^2` of the smooth cone `t = clamp((cos - cosOuter) / (cosInner - cosOuter))`; `punctualAttenuation()` is the CPU
  twin of the shader function and is used by the Canvas2D rasterizer.
- WebGL2 uniform buffers: `BrioLights` (binding 0, rewritten when the environment `version` changes) and `BrioPass`
  (binding 1: camera position + exposure, fog color + mode, fog near / far / density + tone mapping code), written by
  `setPassParameters()` after each `beginFrame()` and uploaded at `endFrame()`.
- `"standard"` shading (`FEATURE_STANDARD`) uses GGX distribution, height-correlated Smith visibility and Schlick
  Fresnel, plus a split-sum environment approximation over the hemisphere colors. Light intensities keep the Lambert
  convention of the other modes (intensity 1 lights a white surface fully), so the direct terms are scaled by PI.
  Emissive is added after lighting; fog then blends toward its color, and the exposure-scaled color is tone mapped
  before sRGB encoding (no HDR render target yet).
- Program variants are built by `buildShaderSources(features)`. A variant that fails to compile or link is logged
  once and its draws are skipped (`#failedPrograms`); it is never thrown from `endFrame()`.
  `SHADER_FEATURE_COMBINATIONS` lists every variant for the offline `glslangValidator` test.
- Canvas2D approximates every lit mode (including `"standard"`) with Lambert luminance per triangle, from world-space
  normals and centroids; fog, tone mapping and emissive are not applied there.



- Making a backend `init()` fall back by itself, or jumping to `canvas2d` on failure. Fallback is the job of the cascade in `initBackend()`.
- Mutating `BrioMesh` arrays after the first render and expecting GPU backends to pick up the change.
- Known limitations (docs/ROADMAP.md): Canvas2D sorts by centroid with no z-buffer, so large triangles can cover objects (`createPlane` with segments is the workaround), and it does not sample textures. There is no PBR, no shadows, no instancing and no tone mapping. `renderStats` does not yet merge backend counters (`drawCalls`, `trianglesRendered`).
- Doc drift: ADR 0001 names `BrioRenderBackend` and `WebGL2Renderer`/`Canvas2DRenderer`, while the code uses `RenderBackend`, `WebGL2Backend` and `Canvas2DBackend`. The `RenderBackend` doc comment promises "visual parity", which Canvas2D does not provide (no textures, no depth buffer). In `RENDERING_STUDY_THREEJS.md`, the row stating lights are "constants in the shader" and the remark that the fallback must still be fixed are stale: the `BrioLights` UBO and the cascade fix both exist. ADR 0003 describes multiple canvases and worker rendering, but today one main-thread canvas plus offscreen static caches is used.
