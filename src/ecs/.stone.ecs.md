# ECS World and Component Storage

## Purpose and Design Decisions

`ECSWorld` and `ComponentStorage` are the internal, data-oriented core behind the public OOP facades (ADR 0002).
All per-entity state lives in Structure-of-Arrays buffers preallocated once for `capacity` slots (default 4096), so
the game loop reads and writes contiguous `TypedArray`s instead of object graphs, and snapshots are plain memory
copies (ADR 0005).

- Buffers per slot: `componentMasks` (`Uint32`), `dirtyFlags` and `aliveFlags` (`Uint8`), `transform2D` and
  `transform3D` (16 floats each), `collider` (8 floats), `rigidBody` (10 floats), `visual` (4 `Uint32`). A component
  of entity `id` starts at `id * STRIDE` (`getTransform2DOffset` and the other offset helpers).
- `ComponentStorageLayout` can disable `transform2D` or `transform3D`; a disabled buffer has length 0. `BrioGame`
  passes `transform3D: false` for the `"2d"` preset so 2D games do not pay for 3D memory (ADR 0004). `layoutFlags`
  (`StorageLayoutFlag`) records the choice and is written into snapshots.
- Allocation is O(1): `createEntity` pops `#freeList` or advances `#nextEntityId` (the high-water mark);
  `destroyEntity` pushes the slot back. `instantiateFrom(prefab)` allocates a slot and `copyEntitySlot` copies every
  component with `copyWithin`.
- Each slot has a `Uint32` generation in `#generations`. A handle is `(entityId, generation)`, and
  `isAlive(id, generation)` detects a handle whose slot was destroyed and recycled.
- `useSharedMemory` backs the buffers with `SharedArrayBuffer` when available, but no Worker transport exists yet
  (deferred: reopened item in TODO.md 3.3; ADR 0003 describes the target architecture only). The flag only changes
  the buffer type; every system still runs on the main thread.

## Invariants

- `createEntity` always calls `resetEntitySlot`, which writes the defaults (2D scale 1 and opacity 1; 3D scale 1,
  quaternion `w = 1`, opacity 1; rigid-body mass 1; visual visibility 1) and marks `TRANSFORM | RENDER` dirty, because
  `destroyEntity` only clears the alive flag and mask and leaves stale component data in the slot.
- `destroyEntity` and `clear()` increment the generation of every affected slot, so a handle captured before the
  call fails `isAlive(id, generation)` even after the slot is reused. Generations are not part of snapshots, and
  `BrioSerializer.restoreSnapshot` calls `clear()`, so every handle re-reads `generationOf` after a restore.
- `destroyEntity` is idempotent and bounds-checked (returns `false` for dead or out-of-range ids), so a double
  destroy cannot corrupt `activeCount` or push a slot twice onto the free-list.
- Iteration (`query`, `clearAllDirty`, `clear`) stops at `highWaterMark`, not `capacity`, so cost scales with the
  slots ever used. `query(mask, out)` truncates and refills the caller's array to keep the loop allocation-free.
- Buffers are never reallocated or replaced after construction, because facades and `BrioVec2`/`BrioVec3` views hold
  direct references to them and to offsets inside them. Capacity is therefore fixed; exceeding it throws in
  `createEntity`.

## Integration Contracts

- Facades (`objects`) bind with `bindECS(storage, entityId, adopt)` and use fixed offsets: 2D `[0-1]` position,
  `[2-3]` size, `[4-5]` scale, `[6-7]` pivot, `[8-9]` skew, `[10-11]` renderSize, `[12]` rotation, `[13]` opacity,
  `[14]` layer depth; 3D `[0-2]` position, `[3-5]` scale, `[6-8]` Euler rotation, `[9-12]` quaternion, `[13]` opacity,
  `[14]` layer depth. Index 15 is unused in both. The defaults in `resetEntitySlot` depend on these offsets.
- The `visual` stride slot `VISUAL_VISIBILITY_OFFSET` (2) holds the visibility flag of bound 2D and 3D transforms
  (`1` visible, default), so snapshots capture visibility.
- `DirtyFlag.RENDER` is read by `BrioCompositor` to invalidate `"static"` layer caches; the compositor calls
  `world.clearAllDirty()` at the end of every frame.
- `BrioSerializer` round-trips the allocator through `highWaterMark`, `activeCount`, `getFreeListSnapshot()` and
  `restoreInternalState()`.
- `BrioGame` owns one world (layout per preset); every `BrioScene` owns another, created with both transform
  buffers (or an explicit constructor layout) and narrowed to the game preset by `BrioScene.useLayout()`, which
  replaces the scene world while it is still uncaptured.

## Anti-Patterns

- Storing an `entityId` without its generation, or checking only `isAlive(id)`: after recycling, the id points to an
  unrelated entity.
- Calling `query()` without an `out` array inside the loop, or adding per-frame sorting or `Array.from` over masks.
- Adding a component as a JS object map. Component data belongs in a strided buffer with an offset helper, defaults
  in `resetEntitySlot`, a copy in `copyEntitySlot` and a section in the snapshot format (with a version bump).
- Treating `COLLIDER`, `RIGIDBODY` and the rest of `VISUAL` as authoritative: these buffers are allocated, reset,
  copied and serialized, but apart from the visibility slot no code outside `ecs/` and `storage/` reads or writes
  them today. Colliders and rigid bodies live in JS fields of the facades and physics classes (deferred design gap).
  Custom user components are not supported yet (TODO.md 8.3).
