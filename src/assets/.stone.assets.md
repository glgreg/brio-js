# Assets and Model Loaders

## Purpose and Design Decisions

- Assets are passive data objects identified by `name`. `BrioGame.preload()` loads them and stores them in `BrioAssetManager` maps. Objects refer to them by name (`BrioObject2D.sprite`, `BrioObject3D.mesh` / `.material`), never by reference, which keeps ECS-backed objects serializable.
- 2D: `BrioSprite` owns an `HTMLImageElement` and may carry a `sourceRect` (`x`, `y`, `width`, `height` in image pixels). With a `sourceRect`, `BrioSpriteRenderer.renderObject` draws only that region (9-argument `drawImage`) scaled to the render size, and `size` reports the rectangle size even after preload measures the whole image. `BrioSpriteSheet` is a uniform grid (`cellWidth`, `cellHeight`, `columns`, `rows`) over a `TextureRegistry.acquire(src)` texture. `getCellRect(i)` returns a cell's rectangle, `createSprite(name, cell = 0)` returns a sprite showing that cell, and `createCellSprites()` returns sprites named `"<sheet>_cell_<i>"`, the frame names that `createAnimation(name, start, end)` uses. `BrioAtlas` holds named, arbitrary regions (`defineRegion`, `getRegion`, `regionNames`, or a `regions` record in the constructor) over one image, and `createSprite(region, name?)` returns a sprite showing one region. `BrioAnimation` advances frames by `deltaTime` (loop, one-shot with `onComplete`, `pingPong`). `BrioTileMap` holds a row-major `Uint32Array` of tile ids (0 means empty; negative or non-finite ids are stored as 0) and merges solid tiles into minimal AABB colliders (`buildMergedColliders`, offset by `position`). See Tile maps below.
- Texture sharing: `BrioSpriteSheet` and `BrioAtlas` share decoded images through `TextureRegistry` (`BrioAtlas.mount()` calls `BrioTexture.decode()` and returns its `ImageBitmap`). `BrioSprite` keeps its own `Image` because `BrioGame` preload assigns `element.onload` per sprite, and on a shared element the last assignment would replace the others and leave earlier preload promises pending. Sharing sprite images needs preload to use `addEventListener("load")` or `element.decode()` first.
- Tile maps: a `BrioTileMap` is built from a `number[][]` matrix (columns from the first row), a `FlatTileGrid` (`columns`, `rows`, row-major `tiles`), `fromTiled(json, { name, layer, tileset, solidTileIds })` or `fromCSV(name, tw, th, csv, solidTileIds?)`. Its optional `tileset` (`BrioSpriteSheet`) draws id `n > 0` as cell `n - 1` in row-major order; ids beyond the sheet's cells draw nothing. `position` (a `BrioVec2`, the world offset of the top-left corner), `visible` and `opacity` (clamped to [0, 1]) only affect drawing and, for `position`, `worldToTile` / `getTileAtWorld` and the colliders. `fill(id, col, row, cols, rows)` writes a clipped rectangle, and `captureTiles()` / `restoreTiles(data)` copy the whole grid for checkpoints. Tile flipping and rotation are not supported.
- Tile map rendering is chunked: the map is split into chunks of up to 16x16 tiles (fewer when a tile is wider or taller than 128 px, so a chunk raster stays at or under 2048 px). `rendering/BrioTileMapRenderer.ts` (`drawTileMaps`, internal) rasterizes each visible chunk once into an offscreen surface and then draws it with one `drawImage`; it keeps the rasters in a module-level `WeakMap` keyed by the map. A map keeps one version counter per chunk, so `setTile` and `fill` re-rasterize only the chunks they touched, and a tileset change or `restoreTiles` re-rasterizes all of them. Chunk surfaces are reused once a map holds 256 of them (the least recently drawn one outside the view is taken), and a map with more visible chunks than that keeps one per visible chunk instead of re-rasterizing every frame.
- Tiled import accepts orthogonal, finite maps whose tile layers carry `data` as a plain number array (`encoding` absent or `"csv"`), including tile layers nested in group layers (`tiledLayerNames(json)` lists them). `layer` selects a tile layer by name or by index among tile layers (the first one by default). Gids lose the four Tiled flag bits (flips and the hexagonal rotation) and are made relative to the first tileset (`gid - (firstgid - 1)`, empty below it); gids of later tilesets keep counting past the first tileset. The layer `visible`, `opacity`, `offsetx` and `offsety` become the map's `visible`, `opacity` and `position`.
- `BrioAudio` loads into an `AudioBuffer` and plays through its own gain and a `BrioAudioMixer` bus when Web Audio exists. Otherwise it falls back to `HTMLAudioElement` (see the audio stone).
- 3D: `BrioMesh` stores flat `Float32Array` `positions` (xyz), `normals` (xyz) and `uvs` (uv), plus `Uint16Array | Uint32Array` `indices` (3 per triangle). It has procedural generators (`createBox`, `createPlane(w, d, segments)`, `createSphere`, `createCylinder`) that emit counter-clockwise front faces. `BrioMaterial` has `color` (CSS, sRGB), `shading` (`unlit | flat | lambert`), `opacity` and `alphaCutoff` (both clamped to [0, 1]), `wireframe`, `doubleSided`, and an optional `texture`. `BrioTexture` wraps an image or an `ImageBitmap`; its `filter` (`"linear"` mipmapped, `"nearest"` single level for pixel art) and `wrap` (`"repeat"`, `"clamp"`) are read once by GPU backends at upload, so changing them later has no effect on an uploaded copy. `fromBlob()` decodes with `premultiplyAlpha: "none"` and `colorSpaceConversion: "none"` so GPU backends can sample the result as sRGB data.
- `BrioModel.load()` picks a loader from `format` or from the URL extension, and unknown extensions default to `"glb"`. It fills the `meshes`, `materials`, `meshMaterials`, `warnings` and `boundingBox` fields. `instantiate(name)` creates a single `BrioObject3D` or a root with `"<name>_part_<i>"` children, plus a box collider from the bounding box. A per-mesh material binding (glTF `primitive.material`, OBJ `usemtl`) takes precedence over pairing meshes and materials by index; an empty binding falls back to index pairing.
- `GLBLoader.parse` validates the 12-byte header (magic `glTF`, version 2) and its chunks. Buffers are resolved per glTF `buffers` entry (`resolveGLTFBuffers`): in a GLB the BIN chunk is buffer 0 (when buffer 0 has no `uri`), base64 `data:` buffers are decoded, and `load()` fetches external buffer files (`fetchGLTFExternalBuffers`). Every accessor and embedded image reads from the buffer named by `bufferView.buffer`. `extractModelData` converts `baseColorFactor` from linear to sRGB hex, maps `alphaMode` MASK to `alphaCutoff` and BLEND with opaque factor to a 0.5 cutoff, and bakes the world matrix of the first node that instances each mesh into its vertices (skinned nodes are skipped). It generates missing indices, flat normals and zero UVs. `decodeTextures` decodes each image once per key with `createImageBitmap` and shares it across materials. `GLTFLoader.parse(text, buffers)` takes buffers indexed like the glTF `buffers` array and decodes `data:` entries itself; `load()` fetches the external ones.
- OBJ: `parseOBJGeometry` (`loaders/objGeometry.ts`) is the single OBJ geometry parser. It reads `v`/`vt`/`vn`/`f` with fan triangulation and negative (relative) indices, computes flat normals when the file has no `vn`, and uses `Uint32Array` indices above 65535 vertices. `OBJLoader.parse` splits meshes on `o`/`g` and on `usemtl` changes inside a group (`"<group>_<material>"`, duplicate names get `_<n>`), binds each mesh to its `usemtl` material through `meshMaterials`, and reports `usemtl` names missing from the `.mtl` in `warnings`. `OBJLoader.load` reads the `.mtl` from `mtlSource` or `mtllib`. `BrioMesh.fromOBJ` uses the same parser with grouping disabled, so every face lands in one mesh.

## Invariants

- Loaded mesh and material names are namespaced as `"<model>/<name>"` (with `mesh_<m>_<p>`, `mat_<i>`, `default` or `group_<n>` as fallbacks). `BrioGame` merges every model into one shared `meshes`/`materials` map, and without the prefix two models with a material called `"Face"` would overwrite each other.
- `BrioTileMap.version` increases on every change that alters what the map draws (a tile value that actually changes, the tileset, `position`, `visible`, `opacity`, `restoreTiles`) and on nothing else. `BrioLayer.isDirty` compares it to the version seen at the last `clearDirty()`, which is how `"static"` layer caches learn about tile edits without a per-frame scan of the grid.
- Chunk versions start at 1 and never return to 0, because the renderer uses 0 to mean "never rasterized". Map dimensions and tile size are fixed after construction (`restoreTiles` throws on a length mismatch), so a chunk's raster size never changes.
- A chunk is marked rasterized only after it was drawn from a tileset texture with a pixel size (`texture.width > 0`: a decoded `ImageBitmap` or a loaded `HTMLImageElement`). Until then the map draws nothing, so an image that finishes loading later is picked up on the next frame instead of leaving blank cached chunks. The decoded `bitmap` is preferred as the source, then the element.
- `drawTileMaps` allocates only when a chunk surface (or a map's cache arrays) is created; chunk lookup, culling, rasterization and drawing read the map's `Uint32Array` and cache typed arrays in place. When a chunk surface has no 2D context (jsdom), the cache switches to drawing the visible tiles directly onto the destination for that map.
- `fromTiled` and `fromCSV` enforce `TILE_MAP_LIMITS` before allocating: at most 4096 columns and rows, tiles of at most 4096 px, CSV sources of at most 128 Mi characters and group layers nested at most 32 deep. Structure is validated (positive integer `width`/`height`/`tilewidth`/`tileheight`, `data.length === width * height`, integer gids in `[0, 2^32)`), and base64 or compressed data, infinite maps and non-orthogonal orientations throw an `Error` that names the problem. Neither importer evaluates code.
- `ModelLoaderLimits` (`limits.ts`) apply to every byte that comes from a file, including `BrioMesh.fromOBJ` input. Defaults: `maxFileBytes` 256 MiB (checked against `Content-Length` before download and against the actual size after, and against each decoded `data:` buffer or image), `maxJsonBytes` 32 MiB, `maxAccessorComponents` 64 Mi (also caps each OBJ group's decoded components), `maxImageDimension` 8192 (read from PNG/GIF/JPEG/WebP headers before decoding), and `maxNodeDepth` 128. A node graph is walked with a `visited` set, so cyclic files terminate. Violations throw `ModelLimitError`. This protects against hostile or corrupt files that would otherwise exhaust memory or read out of bounds. `configureModelLoaderLimits()` changes the limits for every loader at once.
- Accessors are validated (count, component type, stride, offset, buffer index, bufferView range) and decoded into fresh copies. Transform baking therefore never mutates the source buffer. A bufferView pointing at a buffer that is missing throws `ModelLimitError`; an external buffer that was not fetched resolves to an empty buffer and fails the range check. `UNSIGNED_BYTE` indices are promoted to `Uint16Array`.
- A primitive whose indices exceed its vertex count, or whose index count is not a multiple of 3, is skipped with a warning instead of failing the model. Bad indices would read garbage on Canvas2D and fail GPU draw validation.
- Meshes with more than 65535 vertices use `Uint32Array` indices, and backends draw them with `UNSIGNED_INT`.
- A texture decode failure is reported in `warnings` and leaves the material untextured. It never rejects `load()`.
- `BrioSprite.sourceRect` is copied on assignment; a rectangle with a non-positive width or height clears it. The renderer reads it without allocating.

## Integration Contracts

- `ParsedModelData` (`meshes`, `materials`, `meshMaterials?`, `pendingTextures?`, `warnings?`) is the shared output type of all loaders.
- `GLBLoader.extractModelData(json, buffers, name)` and `extractGLTFAccessor(json, buffers, i)` accept a single `ArrayBuffer` (buffer 0) or an array indexed like `json.buffers`.
- GPU backends cache `BrioMesh` and `BrioTexture` in `WeakMap`s and treat geometry as immutable after the first draw.
- All 2D sprite drawing goes through `BrioSpriteRenderer.renderObject` (the compositor calls it for every 2D pass and for static layer caches); no backend draws sprites directly.
- `BrioGame` logs `model.warnings` after preload. `getEmptyInstance()` fallbacks (`BrioSprite`, `BrioModel`, `BrioMesh`) back lookups of unknown names.
- `drawTileMaps(ctx, maps, left, top, right, bottom, scale = 1)` expects `ctx` in world space (camera transform applied) and the visible world rectangle in world pixels, already expanded by the caller for rotation; `scale` wraps the draw in `ctx.scale(scale, scale)` for callers whose camera transform works in `game.scale`d pixels. It returns the number of chunks drawn. `BrioLayer.tileMaps` are drawn before the layer's objects.
- Chunk rasters copy `imageSmoothingEnabled` / `imageSmoothingQuality` from the destination context when they are rasterized, so `game.rendering.mode` applies to tiles as it does to sprites.
- `SpriteSourceRect` is exported from `src/index.ts` and is also the value type of the `BrioAtlas` `regions` constructor record (`Record<string, SpriteSourceRect>`).

## Custom Shaders

- `BrioShader` holds GLSL hooks (inline, or a `.glsl` file fetched by `load()` during `preload()`, split at a
  `// @vertex` line). Sources are checked against `maxLength` and the reserved `brio_` prefix; every source change
  bumps `version`, which the backend compares to rebuild its programs (hot reload). `id` is process-unique and part of
  the program cache key.
- `BrioMaterial.shader` is a `BrioShader` or the name of a preloaded one; `preload()` replaces names by the loaded
  shader once every asset of that preload settled (unknown names are warned about). `parameters` maps uniform names
  to numbers, 2-4 component arrays or CSS colors; `set()` writes one.

## Anti-Patterns

- Registering a loaded mesh or material under its raw source name, or bypassing `fetchLimited`/`assertByteLimit` in a new loader.
- Adding a second OBJ parser instead of extending `parseOBJGeometry`.
- Known limitations (docs/ROADMAP.md): glTF skinned meshes render in bind pose and animations are ignored. `BrioTileMap` has no flipped or rotated tiles, no animated tiles, no isometric/hexagonal maps, no infinite (chunked) Tiled maps and no base64/compressed Tiled data; only the first tileset's `firstgid` is applied. With smoothing on and a fractional zoom, adjacent chunk images can show hairline seams. OBJ `.mtl` parsing reads only `Kd`, `d` and `Tr` (no texture maps). `BrioSprite` does not share decoded images through `TextureRegistry` (see Texture sharing above).
