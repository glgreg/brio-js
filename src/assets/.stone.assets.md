# Assets and Model Loaders

## Purpose and Design Decisions

- Assets are passive data objects identified by `name`. `BrioGame.preload()` loads them and stores them in `BrioAssetManager` maps. Objects refer to them by name (`BrioObject2D.sprite`, `BrioObject3D.mesh` / `.material`), never by reference, which keeps ECS-backed objects serializable.
- 2D: `BrioSprite` owns an `HTMLImageElement` and may carry a `sourceRect` (`x`, `y`, `width`, `height` in image pixels). With a `sourceRect`, `BrioSpriteRenderer.renderObject` draws only that region (9-argument `drawImage`) scaled to the render size, and `size` reports the rectangle size even after preload measures the whole image. `BrioSpriteSheet` is a uniform grid (`cellWidth`, `cellHeight`, `columns`, `rows`) over a `TextureRegistry.acquire(src)` texture. `getCellRect(i)` returns a cell's rectangle, `createSprite(name, cell = 0)` returns a sprite showing that cell, and `createCellSprites()` returns sprites named `"<sheet>_cell_<i>"`, the frame names that `createAnimation(name, start, end)` uses. `BrioAtlas` holds named, arbitrary regions (`defineRegion`, `getRegion`, `regionNames`, or a `regions` record in the constructor) over one image, and `createSprite(region, name?)` returns a sprite showing one region. `BrioAnimation` advances frames by `deltaTime` (loop, one-shot with `onComplete`, `pingPong`). `BrioTileMap` holds a grid of tile ids (0 means empty) and merges solid tiles into minimal AABB colliders (`buildMergedColliders`).
- Texture sharing: `BrioSpriteSheet` and `BrioAtlas` share decoded images through `TextureRegistry` (`BrioAtlas.mount()` calls `BrioTexture.decode()` and returns its `ImageBitmap`). `BrioSprite` keeps its own `Image` because `BrioGame` preload assigns `element.onload` per sprite, and on a shared element the last assignment would replace the others and leave earlier preload promises pending. Sharing sprite images needs preload to use `addEventListener("load")` or `element.decode()` first.
- `BrioAudio` loads into an `AudioBuffer` and plays through its own gain and a `BrioAudioMixer` bus when Web Audio exists. Otherwise it falls back to `HTMLAudioElement` (see the audio stone).
- 3D: `BrioMesh` stores flat `Float32Array` `positions` (xyz), `normals` (xyz) and `uvs` (uv), plus `Uint16Array | Uint32Array` `indices` (3 per triangle). It has procedural generators (`createBox`, `createPlane(w, d, segments)`, `createSphere`, `createCylinder`) that emit counter-clockwise front faces. `BrioMaterial` has `color` (CSS, sRGB), `shading` (`unlit | flat | lambert`), `opacity` and `alphaCutoff` (both clamped to [0, 1]), `wireframe`, `doubleSided`, and an optional `texture`. `BrioTexture` wraps an image or an `ImageBitmap`. `fromBlob()` decodes with `premultiplyAlpha: "none"` and `colorSpaceConversion: "none"` so GPU backends can sample the result as sRGB data.
- `BrioModel.load()` picks a loader from `format` or from the URL extension, and unknown extensions default to `"glb"`. It fills the `meshes`, `materials`, `meshMaterials`, `warnings` and `boundingBox` fields. `instantiate(name)` creates a single `BrioObject3D` or a root with `"<name>_part_<i>"` children, plus a box collider from the bounding box. A per-mesh material binding (glTF `primitive.material`, OBJ `usemtl`) takes precedence over pairing meshes and materials by index; an empty binding falls back to index pairing.
- `GLBLoader.parse` validates the 12-byte header (magic `glTF`, version 2) and its chunks. Buffers are resolved per glTF `buffers` entry (`resolveGLTFBuffers`): in a GLB the BIN chunk is buffer 0 (when buffer 0 has no `uri`), base64 `data:` buffers are decoded, and `load()` fetches external buffer files (`fetchGLTFExternalBuffers`). Every accessor and embedded image reads from the buffer named by `bufferView.buffer`. `extractModelData` converts `baseColorFactor` from linear to sRGB hex, maps `alphaMode` MASK to `alphaCutoff` and BLEND with opaque factor to a 0.5 cutoff, and bakes the world matrix of the first node that instances each mesh into its vertices (skinned nodes are skipped). It generates missing indices, flat normals and zero UVs. `decodeTextures` decodes each image once per key with `createImageBitmap` and shares it across materials. `GLTFLoader.parse(text, buffers)` takes buffers indexed like the glTF `buffers` array and decodes `data:` entries itself; `load()` fetches the external ones.
- OBJ: `parseOBJGeometry` (`loaders/objGeometry.ts`) is the single OBJ geometry parser. It reads `v`/`vt`/`vn`/`f` with fan triangulation and negative (relative) indices, computes flat normals when the file has no `vn`, and uses `Uint32Array` indices above 65535 vertices. `OBJLoader.parse` splits meshes on `o`/`g` and on `usemtl` changes inside a group (`"<group>_<material>"`, duplicate names get `_<n>`), binds each mesh to its `usemtl` material through `meshMaterials`, and reports `usemtl` names missing from the `.mtl` in `warnings`. `OBJLoader.load` reads the `.mtl` from `mtlSource` or `mtllib`. `BrioMesh.fromOBJ` uses the same parser with grouping disabled, so every face lands in one mesh.

## Invariants

- Loaded mesh and material names are namespaced as `"<model>/<name>"` (with `mesh_<m>_<p>`, `mat_<i>`, `default` or `group_<n>` as fallbacks). `BrioGame` merges every model into one shared `meshes`/`materials` map, and without the prefix two models with a material called `"Face"` would overwrite each other.
- `ModelLoaderLimits` (`limits.ts`) apply to every byte that comes from a file, including `BrioMesh.fromOBJ` input. Defaults: `maxFileBytes` 256 MiB (checked against `Content-Length` before download and against the actual size after, and against each decoded `data:` buffer or image), `maxJsonBytes` 32 MiB, `maxAccessorComponents` 64 Mi (also caps each OBJ group's decoded components), `maxImageDimension` 8192 (read from PNG/GIF/JPEG/WebP headers before decoding), and `maxNodeDepth` 128. A node graph is walked with a `visited` set, so cyclic files terminate. Violations throw `ModelLimitError`. This protects against hostile or corrupt files that would otherwise exhaust memory or read out of bounds. `configureModelLoaderLimits()` changes the limits for every loader at once.
- Accessors are validated (count, component type, stride, offset, buffer index, bufferView range) and decoded into fresh copies. Transform baking therefore never mutates the source buffer. A bufferView pointing at a buffer that is missing throws `ModelLimitError`; an external buffer that was not fetched resolves to an empty buffer and fails the range check. `UNSIGNED_BYTE` indices are promoted to `Uint16Array`.
- A primitive whose indices exceed its vertex count, or whose index count is not a multiple of 3, is skipped with a warning instead of failing the model. Bad indices would read garbage on Canvas2D and fail GPU draw validation.
- Meshes with more than 65535 vertices use `Uint32Array` indices, and backends draw them with `UNSIGNED_INT`.
- A texture decode failure is reported in `warnings` and leaves the material untextured. It never rejects `load()`.
- `BrioSprite.sourceRect` is copied on assignment; a rectangle with a non-positive width or height clears it. The renderer reads it without allocating.

## Integration Contracts

- `ParsedModelData` (`meshes`, `materials`, `meshMaterials?`, `pendingTextures?`, `warnings?`) is the shared output type of all loaders.
- `GLBLoader.extractModelData(json, buffers, name)` and `extractGLTFAccessor(json, buffers, i)` accept a single `ArrayBuffer` (buffer 0) or an array indexed like `json.buffers`.
- GPU backends cache `BrioMesh` and `BrioTexture` in `WeakMap`s and treat geometry as immutable after the first draw.
- All 2D sprite drawing goes through `BrioSpriteRenderer.renderObject` (the compositor calls it for every 2D pass and for static layer caches); no backend draws sprites directly.
- `BrioGame` logs `model.warnings` after preload. `getEmptyInstance()` fallbacks (`BrioSprite`, `BrioModel`, `BrioMesh`) back lookups of unknown names.
- `SpriteSourceRect` and the `regions` constructor record are not re-exported from `src/index.ts` yet; object literals work without the type import.

## Anti-Patterns

- Registering a loaded mesh or material under its raw source name, or bypassing `fetchLimited`/`assertByteLimit` in a new loader.
- Adding a second OBJ parser instead of extending `parseOBJGeometry`.
- Known limitations (docs/ROADMAP.md): glTF skinned meshes render in bind pose and animations are ignored. `BrioTileMap` has no renderer yet (chunked `"static"` layer rendering is planned). OBJ `.mtl` parsing reads only `Kd`, `d` and `Tr` (no texture maps). `BrioSprite` does not share decoded images through `TextureRegistry` (see Texture sharing above).
