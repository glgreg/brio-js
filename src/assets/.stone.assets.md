# Assets and Model Loaders

## Purpose and Design Decisions

- Assets are passive data objects identified by `name`. `BrioGame.preload()` loads them and stores them in `BrioAssetManager` maps. Objects refer to them by name (`BrioObject2D.sprite`, `BrioObject3D.mesh` / `.material`), never by reference, which keeps ECS-backed objects serializable.
- 2D: `BrioSprite` owns an `HTMLImageElement`, and `BrioAtlas` decodes a whole image to an `ImageBitmap` through `mount()`. `BrioSpriteSheet` is a uniform grid (`cellWidth`, `cellHeight`, `columns`, `rows`) over a `TextureRegistry.acquire(src)` texture. `getCellRect(i)` returns a cell's rectangle. `createAnimation(name, start, end)` creates frames named `"<sheet>_cell_<i>"`. `BrioAnimation` advances frames by `deltaTime` (loop, one-shot with `onComplete`, `pingPong`). `BrioTileMap` holds a grid of tile ids (0 means empty) and merges solid tiles into minimal AABB colliders (`buildMergedColliders`).
- `BrioAudio` loads into an `AudioBuffer` and plays through its own gain and a `BrioAudioMixer` bus when Web Audio exists. Otherwise it falls back to `HTMLAudioElement` (see the audio stone).
- 3D: `BrioMesh` stores flat `Float32Array` `positions` (xyz), `normals` (xyz) and `uvs` (uv), plus `Uint16Array | Uint32Array` `indices` (3 per triangle). It has procedural generators (`createBox`, `createPlane(w, d, segments)`, `createSphere`, `createCylinder`) that emit counter-clockwise front faces. `BrioMaterial` has `color` (CSS, sRGB), `shading` (`unlit | flat | lambert`), `opacity` and `alphaCutoff` (both clamped to [0, 1]), `wireframe`, `doubleSided`, and an optional `texture`. `BrioTexture` wraps an image or an `ImageBitmap`. `fromBlob()` decodes with `premultiplyAlpha: "none"` and `colorSpaceConversion: "none"` so GPU backends can sample the result as sRGB data.
- `BrioModel.load()` picks a loader from `format` or from the URL extension, and unknown extensions default to `"glb"`. It fills the `meshes`, `materials`, `meshMaterials`, `warnings` and `boundingBox` fields. `instantiate(name)` creates a single `BrioObject3D` or a root with `"<name>_part_<i>"` children, plus a box collider from the bounding box. A per-primitive material binding (glTF) takes precedence over pairing meshes and materials by index.
- `GLBLoader.parse` validates the 12-byte header (magic `glTF`, version 2) and its chunks. `extractModelData` converts `baseColorFactor` from linear to sRGB hex, maps `alphaMode` MASK to `alphaCutoff` and BLEND with opaque factor to a 0.5 cutoff, and bakes the world matrix of the first node that instances each mesh into its vertices (skinned nodes are skipped). It generates missing indices, flat normals and zero UVs. `decodeTextures` decodes each image once per key with `createImageBitmap` and shares it across materials. `GLTFLoader` decodes base64 `data:` buffers or fetches `.bin` files, then delegates to `GLBLoader.extractModelData`. `OBJLoader` parses `v`/`vt`/`vn`/`f` with fan triangulation, splits meshes on `o`/`g`, and reads `.mtl` from `mtlSource` or `mtllib`.

## Invariants

- Loaded mesh and material names are namespaced as `"<model>/<name>"` (with `mesh_<m>_<p>`, `mat_<i>`, `default` or `group_<n>` as fallbacks). `BrioGame` merges every model into one shared `meshes`/`materials` map, and without the prefix two models with a material called `"Face"` would overwrite each other.
- `ModelLoaderLimits` (`limits.ts`) apply to every byte that comes from a file. Defaults: `maxFileBytes` 256 MiB (checked against `Content-Length` before download and against the actual size after), `maxJsonBytes` 32 MiB, `maxAccessorComponents` 64 Mi, `maxImageDimension` 8192 (read from PNG/GIF/JPEG/WebP headers before decoding), and `maxNodeDepth` 128. A node graph is walked with a `visited` set, so cyclic files terminate. Violations throw `ModelLimitError`. This protects against hostile or corrupt files that would otherwise exhaust memory or read out of bounds. `configureModelLoaderLimits()` changes the limits for every loader at once.
- Accessors are validated (count, component type, stride, offset, bufferView range) and decoded into fresh copies. Transform baking therefore never mutates the source buffer. `UNSIGNED_BYTE` indices are promoted to `Uint16Array`.
- A primitive whose indices exceed its vertex count, or whose index count is not a multiple of 3, is skipped with a warning instead of failing the model. Bad indices would read garbage on Canvas2D and fail GPU draw validation.
- Meshes with more than 65535 vertices use `Uint32Array` indices, and backends draw them with `UNSIGNED_INT`.
- A texture decode failure is reported in `warnings` and leaves the material untextured. It never rejects `load()`.

## Integration Contracts

- `ParsedModelData` (`meshes`, `materials`, `meshMaterials?`, `pendingTextures?`, `warnings?`) is the shared output type of all loaders.
- GPU backends cache `BrioMesh` and `BrioTexture` in `WeakMap`s and treat geometry as immutable after the first draw.
- `BrioGame` logs `model.warnings` after preload. `getEmptyInstance()` fallbacks (`BrioSprite`, `BrioModel`, `BrioMesh`) back lookups of unknown names.

## Anti-Patterns

- Registering a loaded mesh or material under its raw source name, or bypassing `fetchLimited`/`assertByteLimit` in a new loader.
- Known limitations (docs/ROADMAP.md): glTF skinned meshes render in bind pose and animations are ignored. `BrioTileMap` has no renderer yet (chunked `"static"` layer rendering is planned).
- Limits in the code: `GLTFLoader.parse` only uses the first binary buffer (`bufferView.buffer` is ignored), so multi-buffer glTF files are read incorrectly. `OBJLoader` ignores `usemtl`, so OBJ materials pair with groups by index. `BrioMesh.fromOBJ` is a second OBJ parser that skips `ModelLoaderLimits`.
- Code/doc discrepancies: `BrioSprite` carries no source rectangle, and `BrioSpriteRenderer` draws the whole image. `BrioSpriteSheet.createSprite()` therefore yields a sprite showing the full sheet at cell size, not a single cell. The GLOSSARY defines `BrioAtlas` as named sub-regions, but the class only holds one decoded image. The flyweight `TextureRegistry` (architecture.md) is used only by `BrioSpriteSheet`: `BrioSprite` and `BrioAtlas` each create their own `Image`.
